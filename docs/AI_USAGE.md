## 2. 사용한 도구

| 도구 | 용도 |

| (작성자 확인: 그 외 사용한 도구가 있으면 기재) | |

연구 과정에서 데이터 생성에 쓴 모델(Qwen3-8B, Qwen3-VL-32B)은 코딩 도구가 아니라 실험의 구성 요소다. 이들의 역할은 결과보고서 3.1절에 기술했다. 구간 라벨 표본 312개에 대한 2차 의견은 Claude에게 받았고, 이 사실도 결과보고서에 적었다.

## 5. AI 도구를 활용한 작업의 구체적 내용

### 5.1 서버 어댑터 (`server/app.py`)

- 영상을 순차 디코딩하며 일정 길이의 창으로 나누는 `extract_windows`
- 창을 8등분해 구간마다 프레임 차분이 가장 큰 프레임을 고르는 `pick_change_frames`
- 프레임 8장과 고정 지시문으로 vLLM의 chat completions API를 호출하는 `vllm_describe`
- 모델 출력에서 JSON을 추출하고 열거형 값을 정규화하는 `parse_log`
- bge-m3를 transformers로 직접 불러와 CLS 토큰 임베딩을 만드는 `load_embedder`, `embed_texts`
- `/describe`, `/embed`, `/health` 엔드포인트와 오류 코드 처리

### 5.2 백엔드 통합

- `motion_logs` 테이블의 열 추가와 기존 DB를 위한 마이그레이션 함수
- 임베딩을 float32 BLOB으로 저장하고 읽는 함수
- 어댑터 응답의 창 목록을 첫 창은 갱신, 나머지는 추가하는 방식으로 기록하는 `_store_logs`
- 기간·이상 여부·유형 조건의 로그 조회와 numpy 내적 기반의 유사도 검색
- `/api/logs`의 필터 파라미터와 `/api/logs/search`
- 전처리 결과 파일의 fps 기록 방식 수정과 최소 높이 조건

### 5.3 프론트엔드 통합

- 로그 목록의 검색창, 이상만 보기 토글, 판정·장소·유사도 배지
- 재생 타임라인의 창 구간 막대와 색 구분
- 구간 로그 목록의 배지, 창 시각 표시, 클릭 이동
- 이상 유형의 한국어 표시명 모듈과 관련 스타일

### 5.4 검증

AI 도구가 작성한 코드는 다음 방법으로 확인했다.

- UCF-Crime 영상 6편을 어댑터에 올려 창별 판정 확인
- 창 길이 20초와 60초의 결과 비교
- 깨진 파일, 2초짜리 영상, vLLM이 꺼진 상태에서의 응답 코드 확인
- 영상 2편을 백엔드에 녹화로 넣어 로그 12개 생성, 필터, 검색 3개 질의, 녹화 상세, Range 응답 확인
- 프론트엔드 빌드 통과 확인

(작성자 확인: 위 검증 중 본인이 직접 수행하거나 결과를 직접 확인한 범위를 기재)

### 5.5 문서와 정리

- README, 개발 문서, 결과보고서, 본 보고서의 초안 작성
- 소스 주석을 기능 설명 위주로 정리
- 실행 스크립트 4개와 환경변수 예시 파일 작성

### 6.2 설계와 결정

- 출력을 자유 문장에서 고정 스키마의 JSON으로 바꾸고 이상 판정을 출력 필드에 포함시키는 방향

- 구간 라벨 정책 (사건과 직후 결과는 이상, 사건 전 장면과 사후 도착은 정상)
- teacher 모델이 판정 필드를 쓰지 않고 데이터셋 라벨을 코드로 넣는 방식
- 재현율을 우선해 1차 학습 모델을 최종 모델로 선택
- 서버와 클라이언트를 분리하는 배치와 기본 창 길이 20초
