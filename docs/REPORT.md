## 1. 개요

### 1.1 한 줄 소개

CCTV 영상에서 움직임 구간을 녹화하고, LoRA로 학습한 시각 언어 모델이 구간마다 장소·객체·행동·이상 여부·이상 유형·요약을 담은 한국어 JSON 로그를 만들어 저장·검색하는 시스템이다.

### 1.2 배경과 목표

캡스톤디자인에서 움직임 감지 녹화와 VLM 한 줄 설명을 갖춘 CCTV 모니터링 시스템을 만들었다. 이 시스템의 로그는 자유 형식 문장 하나였다. 문장만으로는 이상 여부로 걸러 내거나 유형별로 모아 볼 수 없고, 녹화 하나에 설명이 하나라서 긴 녹화에서는 사건이 어느 시점에 있는지 알 수 없었다.

졸업작품에서는 세 가지를 목표로 했다.

1. VLM 출력을 고정된 스키마의 한국어 JSON으로 바꾼다.
2. 이상 여부와 유형 판정을 같은 출력에 포함시켜 별도 분류기 없이 로그와 판정을 한 번에 얻는다.
3. 구조화된 로그를 기존 시스템에 통합해 이상 필터, 구간 이동, 자연어 검색을 제공한다.

### 1.3 수행 범위

| 구분 | 내용 |
|---|---|
| 데이터 | UCF-Crime 영상과 UCA 주석에서 클립 5,405개와 한국어 로그 구축 |
| 모델 | Qwen3-VL-8B-Instruct에 LoRA 학습 2회 |
| 평가 | 테스트 클립 798개에서 4개 조건 비교 |
| 서버 | vLLM 앞단 어댑터 서버 구현 (창 분할, 프레임 선택, 파싱, 임베딩) |
| 클라이언트 | 백엔드 DB 확장과 검색 API, 프론트엔드 로그·재생 화면 확장 |
| 검증 | GPU 서버에서 UCF-Crime 영상으로 종단 간 API 검증 |

## 2. 시스템 구성

```
[카메라] → client/backend (FastAPI :8800) ← WebSocket/REST → client/frontend (React :5173)
                 │  전처리한 mp4 업로드 (POST /describe)
                 ▼
           server/app.py (어댑터 :8010) → vLLM (LoRA 병합 모델 :8002)
                 │                         bge-m3 임베딩
                 ▼
           창 단위 JSON 로그 + 임베딩 → SQLite
```

| 구성 요소 | 실행 위치 | 기술 |
|---|---|---|
| 프론트엔드 | 클라이언트 PC | React 18, React Router, Zustand, Axios, Vite |
| 백엔드 | 클라이언트 PC | Python, FastAPI, OpenCV, SQLite(WAL), APScheduler, httpx, numpy |
| 어댑터 서버 | GPU 서버 | FastAPI, OpenCV, transformers(bge-m3) |
| 모델 서버 | GPU 서버 | vLLM 0.33, Qwen3-VL-8B-Instruct + LoRA |
| 학습 | GPU 서버 | LLaMA-Factory 0.9.5 |

GPU 서버는 NVIDIA RTX PRO 6000 Blackwell(96 GB) 3장을 갖추고 있다. 추론에는 그중 1장을 쓴다.

## 3. 실험

### 3.1 데이터 구축

**원본.** UCF-Crime은 감시 카메라 영상 1,900편(이상 13개 유형 950편, 정상 950편)이다. 영상 단위 라벨만 있다. UCA는 UCF-Crime 영상에 구간별 영어 문장을 붙인 주석으로, 1,854편에 23,542개 구간이 있다.

**구간 라벨링.** UCA의 구간은 이상 구간이 아니라 무언가 일어난 구간이다. 이상 영상 안에도 평범한 장면이 많다. 이상 영상의 구간 8,347개에 대해 텍스트 모델 Qwen3-8B에게 문장이 해당 유형의 사건 자체인지 전후의 평범한 장면인지를 물어 라벨을 붙였다. 처리 시간은 33초였고 응답 파싱 실패는 없었다. 유형별 이상 비율은 0.20(Explosion, Stealing)에서 0.51(Assault, Robbery) 사이였다.

라벨 정책은 다음과 같이 정했다. 사건 자체와 직후의 결과 장면(쓰러진 사람, 타는 불)은 이상이다. 사건 전의 평범한 장면, 경찰의 사후 도착, 흩어지는 사람들은 정상이다.

유형별 24개씩 312개를 표본으로 뽑았다. 사람이 직접 검수하지는 않았고, 다른 언어 모델(Claude)에게 같은 표본을 읽혀 2차 의견을 받았다. 동의 269개, 애매 36개, 불일치 7개였다. 불일치는 두 가지 경우에 몰렸다. 앞 구간의 맥락을 알아야 판정할 수 있는 경우와, 범행이 평범한 단어로 적힌 경우다. Burglary, Stealing, Shoplifting에 애매한 사례가 많았다.

**클립 생성.** 겹치는 구간을 합치고 3초 미만은 버렸다. 60초를 넘으면 앞 60초만 썼다. 이상 구간 전부, 정상 영상에서 편당 최대 4개, 이상 영상 속 정상 구간을 선별했다. 클립마다 프레임 8장을 두 가지 방식으로 뽑았다.

- **변화량 기준**: 구간을 8등분하고 각 등분에서 프레임 차분이 가장 큰 1장
- **균등 기준**: 각 등분의 가운데 1장

| | 이상 | 정상 | 합 |
|---|---|---|---|
| 학습 (검증 포함) | 1,696 | 2,911 | 4,607 |
| 테스트 | 231 | 567 | 798 |
| 합 | 1,927 | 3,478 | 5,405 |

분할은 UCF-Crime의 공식 Anomaly_Train / Anomaly_Test를 따랐다. 검증 세트는 학습 영상의 10%를 영상 단위로 분리했다.

**로그 생성.** Qwen3-VL-32B-Instruct에 변화량 기준 프레임 8장과 해당 구간의 UCA 영어 문장을 주고 `scene`, `objects`, `action`, `summary`를 한국어로 쓰게 했다. `is_anomaly`와 `anomaly_type`은 모델이 쓰지 않고 데이터셋 라벨에서 코드로 넣었다. 큰 모델의 오판이 판정 라벨에 섞이지 않게 하기 위해서다. 5,405개 생성에 약 100분이 걸렸고 실패는 1개였다.

파일럿 300개에서 금지 표현(의도·감정 추측, 외모 평가)은 2개 검출되었다. `action`이 60자를 넘는 비율이 23%, `summary`가 40자를 넘는 비율이 41%여서 길이 한도를 각각 80자와 60자로 올렸다.

### 3.2 학습

| 항목 | 값 |
|---|---|
| 베이스 모델 | Qwen/Qwen3-VL-8B-Instruct |
| 방식 | LoRA rank 32, alpha 64, dropout 0.05 |
| 학습 대상 | 언어 모델만. 비전 인코더와 프로젝터는 고정 |
| 입력 | 클립당 프레임 8장 + 고정 지시문 |
| 배치 / 학습률 / 에폭 | 유효 16 / 1e-4 (cosine) / 3 |

학습은 두 번 했다. 두 번째는 이상 영상 속 정상 구간(hard negative)을 늘린 것이다.

| | 학습 / 검증 클립 | eval loss | 학습 시간 |
|---|---|---|---|
| 1차 (B) | 3,776 / 430 | 0.3655 | 84분 |
| 2차 (B2) | 4,154 / 453 | 0.3596 | 약 95분 |

두 학습의 loss는 거의 같다. loss에 기여하는 토큰 대부분이 묘사 필드여서 판정 성능의 차이는 loss로 드러나지 않았다.

### 3.3 평가 설계

테스트 클립 798개(이상 231, 정상 567)로 네 조건을 비교했다.

| 조건 | 모델 | 프레임 | 목적 |
|---|---|---|---|
| A | 베이스 모델 + 같은 지시문 | 변화량 | LoRA의 효과를 재는 기준 |
| B | 1차 LoRA | 변화량 | 주 모델 |
| C | 1차 LoRA | 균등 | 프레임 선택 방식 비교 |
| B2 | 2차 LoRA | 변화량 | hard negative 증량 효과 |

지표는 JSON 파싱 성공률, 이상 판정의 정확도·정밀도·재현율·F1, 이상 클립에 한정한 유형 정확도다.

### 3.4 결과

| | 파싱 | 정확도 | 정밀도 | 재현율 | F1 | 유형 정확도 |
|---|---|---|---|---|---|---|
| A 베이스 | 0.932 | 0.713 | 0.610 | 0.516 | 0.559 | 0.177 |
| **B LoRA** | 0.999 | 0.736 | 0.534 | **0.674** | **0.596** | 0.274 |
| C LoRA + 균등 | 1.000 | 0.738 | 0.540 | 0.645 | 0.588 | 0.277 |
| B2 LoRA + hard neg | 0.999 | 0.751 | 0.571 | 0.576 | 0.573 | 0.260 |

정상 클립을 이상으로 판정한 비율을 클립의 출처별로 나누면 다음과 같다.

| | 정상 영상의 클립 (n≈313) | 이상 영상 속 정상 클립 (n≈254) |
|---|---|---|
| A | 0.03 | 0.26 |
| B | 0.06 | 0.46 |
| C | 0.05 | 0.44 |

### 3.5 분석

**스키마 준수.** 파싱 성공률이 0.932에서 0.999로 올랐다. 베이스 모델은 `Fire`처럼 유형 목록에 없는 값을 출력했고 LoRA 모델은 목록 안의 값만 출력했다. 유형 정확도는 0.177에서 0.274로 올랐다.

**재현율과 정밀도.** 재현율은 0.516에서 0.674로 올랐고 정밀도는 0.610에서 0.534로 내렸다. F1은 0.559에서 0.596이 되었다.

**오탐의 출처.** LoRA 모델의 오탐은 대부분 이상 영상 속의 정상 구간에서 나왔다. 강도가 일어나기 직전의 편의점 같은 장면이다. 정상 영상에서의 오탐은 6%였다. 모델이 사람의 행동보다 장면의 맥락에 의존하는 비중이 크다는 뜻이다. 베이스 모델의 오탐이 낮은 것(0.26)은 판별력이 좋아서가 아니다. 이상 클립도 정상으로 많이 판정한 결과다.

**hard negative 증량.** B2는 정밀도가 0.534에서 0.571로 오르고 재현율이 0.674에서 0.576으로 내렸다. F1은 소폭 낮다. 판별력이 좋아진 것이 아니라 판정 기준이 정상 쪽으로 옮겨 간 것이다. CCTV 용도에서는 사건을 놓치는 비용이 오탐보다 크다고 보아 B를 최종 모델로 택했다.

**프레임 선택.** 변화량 기준(B)과 균등 기준(C)의 차이는 재현율 0.03, F1 0.008이었다. 의미 있는 차이로 보지 않는다.

**유형 혼동.** 혼동은 의미가 가까운 쌍에 몰렸다. Shoplifting을 Robbery로, Explosion을 Arson으로, Burglary를 Robbery로, Shooting을 Assault로 판정한 경우가 많았다. Explosion(학습 클립 37개), Shooting(39개), Vandalism(57개)은 데이터가 적었다.

## 4. 시스템 구현

### 4.1 어댑터 서버

기존 서버는 모델을 직접 불러와 영상 전체에 한 줄 설명을 반환했다. 이를 vLLM을 호출하는 어댑터로 교체했다. 클라이언트가 쓰던 `POST /describe`의 요청 형식과 `description` 필드는 유지하고 응답에 `logs[]`를 추가했다.

- **창 분할**: 영상을 20초 창으로 나누고 3초 미만의 꼬리는 앞 창에 합친다.
- **프레임 선택**: 창마다 학습 때와 같은 규칙으로 8장을 고른다.
- **모델 호출**: 학습 때와 같은 지시문으로 vLLM을 호출한다. temperature 0.
- **파싱**: JSON 블록을 추출하고 열거형 값을 정규화한다.
- **임베딩**: 로그의 요약과 동작 문장을 bge-m3로 임베딩한다(1024차원).
- **부가 엔드포인트**: 검색 질의용 `POST /embed`, 상태 확인용 `GET /health`.

### 4.2 백엔드

- **DB 확장**: `motion_logs`에 `window_start`, `window_end`, `is_anomaly`, `anomaly_type`, `scene`, `action`, `objects_json`, `summary`, `embedding` 열을 추가했다. 기동 시 없는 열만 추가하므로 이전 DB를 그대로 쓴다.
- **창 단위 로그**: 녹화 하나에 로그 여러 개가 연결된다. 첫 창은 세션 종료 때 만든 행을 갱신하고 나머지는 새 행으로 넣는다. 각 로그의 발생 시각은 녹화 시작 시각에 창 시작을 더한 값이다.
- **필터 API**: `GET /api/logs?anomaly=1&type=Robbery`.
- **검색 API**: `GET /api/logs/search?q=...`. 질의를 서버에서 임베딩하고 DB의 로그 임베딩과 코사인 유사도를 numpy로 계산해 상위 N개를 반환한다.
- **전처리 수정**: 결과 파일에 실제 fps를 기록하고, 축소 후 높이가 240 미만이면 축소하지 않는다.
- **장애 대응**: 서버 주소가 없거나 호출이 실패하면 기본 문구만 기록하고 녹화와 재생은 계속 동작한다.

기존에 있던 움직임 감지, 세션 녹화, 코덱 선택과 remux, Range 스트리밍, 30일 자동 삭제, 런타임 설정은 그대로 쓴다.

### 4.3 프론트엔드

- **로그 페이지**: 자연어 검색창, 이상만 보기 토글(건수 표시), 판정 배지(이상은 빨강과 유형명, 정상은 초록), 장소 배지, 요약과 동작 문장, 녹화 내 오프셋. 이상 로그는 목록 위쪽에 모은다. 검색 결과는 유사도순이며 점수를 표시한다.
- **재생 페이지**: 타임라인에 창 길이만큼의 막대를 그린다. 이상은 빨강, 정상은 파랑이다. 구간 로그 목록에서 항목을 누르면 해당 창으로 이동한다.
- **표시명**: 이상 유형은 내부에서 영문 열거형으로 다루고 화면에서 한국어로 바꾼다.

## 5. 구동 결과

### 5.1 검증 환경

현재까지의 구동 검증은 GPU 서버에서 UCF-Crime 영상을 입력으로 수행했다. 영상을 어댑터에 직접 올리는 방식과, 백엔드에 녹화로 넣어 로그 생성부터 조회·검색까지 확인하는 방식 두 가지다. 프론트엔드는 빌드가 통과하는 것까지 확인했다.

**실제 카메라를 연결한 구동과 브라우저 화면 확인은 아직 수행하지 않았다.** 해당 결과는 5.6절에 추가한다.

### 5.2 처리 시간

| 입력 | 창 | 처리 시간 |
|---|---|---|
| 57초 영상 | 20초 창 3개 | 5.9초 |
| 164초 영상 | 60초 창 3개 | 10.7초 |

창 하나에 약 2초가 걸린다. 창을 순서대로 처리하므로 시간은 창 수에 비례한다. 10분 녹화는 20초 창 30개여서 약 1분이 걸린다. 이 때문에 클라이언트의 응답 대기 시간을 60초에서 300초로 늘렸다.

2초짜리 영상(프레임 8장)도 정상 처리되었다. 깨진 파일은 400, vLLM이 꺼진 상태는 502를 반환했다.

### 5.3 창 길이에 따른 검출 차이

같은 영상을 창 길이만 바꿔 넣었을 때 판정이 달라졌다.

| 영상 | 사건 구간 | 60초 창 | 20초 창 |
|---|---|---|---|
| Robbery050 | 14~56초 | 전부 정상 | 해당 구간에서 Robbery 검출 |
| Fighting003 | 64~102초 | 전부 정상 | 해당 구간에서 Fighting 검출 |
| Shoplifting001 | 25~46초, 58~74초 | 전부 정상 | 해당 구간에서 Robbery, Shoplifting 검출 |
| Normal 2편 | 없음 | | 17개 창 모두 정상 |
| RoadAccidents001 (45초) | | 이상 검출 | 이상 검출. 유형은 Arson, Assault, Arrest로 달라짐 |

학습 클립의 길이는 3~60초이고 평균은 17초다. 60초 창은 이 분포의 끝이라 사건이 묻혔다. 이 결과에 따라 기본 창 길이를 20초로 정했다.

### 5.4 입력 해상도와 fps에 따른 차이

Robbery050의 20~40초 창은 480×360, 4fps 입력에서는 Robbery로 검출되었다. 같은 영상을 320×240, 3.75fps로 넣었을 때는 정상으로 판정되었다. 모델이 낮은 해상도와 낮은 fps에 민감하다. 실제 카메라 녹화는 1280×720을 640×360으로 줄여 보내므로 앞의 조건에 가깝다.

전처리에서 결과 파일의 fps를 명목값 4로 기록했을 때는 57초 영상이 53.2초로 저장되어 창 시각이 원본과 어긋났다. 실제 fps를 기록하도록 고친 뒤 일치했다.

### 5.5 백엔드 연동

Robbery050과 Normal 영상 1편을 녹화로 넣어 확인했다.

- 로그 12개가 생성되었다(창 3개 + 9개).
- `anomaly=1` 필터와 `type` 필터가 동작했다.
- 자연어 검색 3개 질의 모두 의미가 맞는 창이 1위였다. 예를 들어 "가방을 들고 나감"은 해당 창이 유사도 0.663으로 1위였다.
- 녹화 상세 조회에서 창 9개가 시각순으로 반환되었다.
- 영상 스트리밍의 Range 요청이 206으로 응답했다.

## 6. 결론

### 6.1 달성한 것

- 베이스 모델에 LoRA를 적용해 스키마 파싱 성공률을 0.932에서 0.999로, 이상 재현율을 0.516에서 0.674로, 유형 정확도를 0.177에서 0.274로 올렸다.
- 오탐을 출처별로 나눠 대부분이 사건 영상 속의 정상 구간에서 나온다는 것을 확인했다.
- 구조화 로그를 기존 시스템에 통합해 창 단위 로그, 이상 필터, 타임라인 표시, 자연어 검색을 구현했다.

### 6.2 한계

- **정밀도**: 이상으로 판정한 것 중 절반가량이 오탐이다. 사건이 일어난 장소의 평범한 장면을 이상으로 본다.
- **유형 구분**: 유형 정확도는 0.274다. 의미가 가까운 유형을 구분하지 못한다.
- **입력 조건 민감도**: 창 길이, 해상도, fps가 학습 분포를 벗어나면 판정이 달라진다.
- **라벨 품질**: 구간 라벨은 텍스트 모델이 문장 하나만 보고 붙였고 사람이 검수하지 않았다. 표본에 대한 2차 의견에서 약 14%가 애매하거나 불일치였다.
- **도메인 차이**: 학습 데이터는 공개된 감시 영상이다. 고정된 실내 카메라에서의 성능은 확인하지 않았다.
- **묘사 품질 미평가**: `scene`, `action`, `summary`의 정확성은 정량 평가하지 않았다.

### 6.3 향후 과제

- 실제 카메라 영상 수십 개에 로그를 만들어 추가 학습한다. 도메인 차이를 줄이는 데 효과가 클 것으로 본다.
- 구간 라벨링을 영상 단위로 바꾼다. 한 영상의 문장을 순서대로 한꺼번에 주면 앞 구간의 맥락이 필요한 사례를 처리할 수 있다.
- 창을 겹치게 나누거나 인접 창의 판정을 함께 써서 창 경계에 걸친 사건을 다룬다.
- 묘사 필드를 UCA 문장과의 유사도나 대형 모델 심사로 평가한다.
- 창을 병렬로 처리해 긴 녹화의 지연을 줄인다.
